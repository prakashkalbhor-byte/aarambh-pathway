01Purpose & Scope

The Vendor Registration Portal (VRP) provides a single, controlled channel for prospective and existing vendors to register, submit qualification information, manage their organisation profile, and be onboarded into downstream procurement and finance systems.

In Scope

  • Self-service vendor account creation and email verification.
  • Multi-step registration capturing company, tax, banking, compliance and category data.
  • Document upload (incorporation certificate, tax certificates, insurance, ISO/quality, MSA).
  • Internal review workflow with multi-level approval, clarifications, and rejection.
  • Vendor profile management, re-verification cycles, and change requests.
  • Audit trail of every state transition and field change.
  • Notification (email and in-portal) of status changes and pending actions.

Out of Scope

  • Sourcing, RFx, contract authoring, purchase order issuance and invoice processing (handled by downstream ERP / S2P).
  • Vendor performance scorecards and SRM analytics.
  • Master Data Governance UI for existing vendor records imported historically.

02Definitions & Glossary

VRP
Vendor Registration Portal — the application described in this document.
Vendor
An external legal entity registering to supply goods or services.
Requestor
Internal employee sponsoring a vendor's onboarding.
Approver
Internal user authorised to approve/reject a registration at a given level.
Qualification
The set of checks (tax, sanctions, finance, compliance) a vendor must pass.
MDM
Master Data Management — system of record for the vendor master record.
SLA
Service Level Agreement — committed response or processing time.
PII / PCI
Personally Identifiable Information / Payment Card Industry data.

06Business Rules

BR-001No duplicate active vendors.
A vendor with the same Tax ID and country cannot exist in ACTIVE state more than once. The system blocks publishing if MDM reports an existing active record.
BR-002High-risk geography requires L2.
If country of incorporation is on the Restricted Countries List, the workflow always requires L2 approval and Compliance Officer sign-off, regardless of spend.
BR-003Bank-name mismatch halts onboarding.
If the declared bank account name does not match legal name or registered DBA, the record cannot progress past Finance review without a written justification attached.
BR-004Sanctions hit = freeze.
A positive sanctions or watchlist hit moves the record to ON_HOLD until Compliance dispositions the alert; auto-publishing is disabled.
BR-005Banking changes require dual control.
Any change to bank account details on an active vendor requires two distinct internal approvers and a callback verification with the vendor on a previously verified phone number.
BR-006Expired insurance blocks orders.
If a required insurance document expires and is not renewed within 14 days, the vendor's status is set to SUSPENDED and a suspension event is sent to ERP.

07Process Flows

7.1Happy Path — Self-Service Registration

  1. Vendor lands on portal home, creates an account, verifies email.
  2. Vendor completes wizard sections 1–8, uploads documents, e-signs T&Cs.
  3. System runs automated qualification checks (FR-QUA-01 … 06).
  4. Procurement Reviewer reviews completeness within 2 business days.
  5. Compliance and Finance reviews complete in parallel within 3 business days.
  6. L1 (or L2 if BR-002 applies) Approver approves.
  7. System requests Vendor ID from MDM, publishes to ERP, sends welcome pack.

7.2Clarification Loop

  1. Reviewer marks one or more fields with structured comments and returns the record.
  2. Vendor receives a single notification listing all open items.
  3. Vendor edits only flagged fields; system tracks deltas and presents them to the reviewer on resubmission.
  4. SLA timer resumes for the reviewer once the vendor resubmits.

09Assumptions, Risks & Dependencies

Assumptions

  • The corporate identity provider supports OIDC and SCIM for internal users.
  • ERP exposes (or can expose) a synchronous vendor-creation API.
  • MDM is the system of record for the Vendor ID.
  • Existing UNSPSC L3 taxonomy is available as reference data.

Risks

  • Third-party sanctions service latency could breach SLA → mitigated with async screening and caching.
  • Data residency requirements may fragment hosting → addressed in TRD §3.
  • Change-management impact on procurement teams → covered by training plan.

10Acceptance Criteria

  1. All MUST requirements pass functional UAT with 0 critical and ≤ 3 major defects.
  2. End-to-end happy path completes in < 35 minutes for a representative test vendor.
  3. SLA dashboards populate within 5 minutes of state transitions in steady state.
  4. WCAG 2.2 AA audit report shows no Level A or AA failures on the vendor journey.
  5. Penetration test produces no Critical findings and ≤ 2 High findings, all remediated before go-live.
